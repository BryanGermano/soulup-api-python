1. TEMA E SOLUCAO PROPOSTA
A Soul Up incentiva ações ambientais por meio de desafios, participação comunitária
e reconhecimento. O programa Python permite gerenciar desafios de sustentabilidade
persistidos no Oracle e consultar os dados do projeto e de uma API externa.

2. ARQUITETURA E ORGANIZACAO
menu.py: menus com repetição, leitura de opções, validação de entrada, dicionários
para os campos dos desafios e chamadas HTTP. A senha de funcionário é lida sem
exibição; o token fica somente em memória. O menu não conecta diretamente ao banco.

app.py: API Flask com funções de validação, autenticação, permissões, regras de
negócio e tratamento de erros. As mesmas rotas podem ser utilizadas pelo terminal
e por clientes web. Nenhuma gravação HTTP é repetida automaticamente.

database.py: tabelas SQLAlchemy, chaves estrangeiras, restrições, sequências Oracle
e transações. Tabelas Python têm prefixo SU_PY_. init_db.py inicializa tabelas
ausentes sem apagar registros existentes.

Exportação: a API consulta os registros e retorna uma lista JSON. O menu grava
essa lista em arquivo UTF-8, com data/hora no nome, por meio de um gerenciador de
contexto que fecha o arquivo. Erros de rede, entrada, autorização e arquivo são
apresentados ao operador. O encerramento usa finally para tentar revogar a sessão.

3. DEMONSTRACAO DOS REQUISITOS
Menus/submenus (10 pontos): executar menu.py e navegar no menu principal e no
submenu CRUD de desafios, voltando com zero.

CRUD e JSON (30 pontos): autenticar funcionário; inserir um desafio; consultar
todos e por ID; alterar descrição, categoria, pontos e estado ativo; exportar e
abrir o arquivo JSON; excluir com confirmação e consultar novamente.
Usar um desafio de demonstração sem ações vinculadas. Para desafios com histórico,
a API impede a exclusão; o operador deve desativá-los na alteração.

API externa (20 pontos): demonstrar as consultas de desafios ou grupos Java no
submenu de consultas, explicando a função java() em app.py e o tratamento de
indisponibilidade. A URL é configurada por SOULUP_API_URL.

Relevância ao projeto / relação com o frontend (10 pontos): demonstrar a relação
dos desafios com sustentabilidade e explicar os contratos entre os serviços.
O enunciado aceita informações relevantes ao projeto como alternativa ao reflexo
bidirecional completo. Não apresentar telas de desafios Java como se fossem os
registros do CRUD Python.

Vídeo (30 pontos): incluir integrantes, sumário, tema, solução, explicação do
código e execução dos casos acima, além da relação com o frontend.

4. RELACAO COM O FRONTEND
O frontend atual usa Python para cadastro e autenticação com token Bearer mediado
por seu servidor Node. Seu catálogo/CRUD de desafios usa Java e as evidências e
ranking demonstrativos ficam no navegador. O menu opera os desafios Python.
Para compartilhar esse CRUD com as telas, aplicar os ajustes descritos em
INTEGRACAO_FRONTEND.md. A criação deste menu não faz essa sincronização.
